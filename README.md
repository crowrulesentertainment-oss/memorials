# CrowRules Memorials\n\n**A Place Where Memories Live Forever** — CrowRules Entertainment.\n\nThis repository is a ground-up responsive website foundation for a worldwide remembrance and legacy platform. It centers family stewardship, privacy, community history, and respectful remembrance.\n\n## Included\n- Cinematic dark / natural visual system and responsive layouts.\n- Shared navigation, footer, and reusable wing cards.\n- Landing page, About, Hall of Remembrance, submission preview, Candlelight Sanctuary, public-figure archive, historical archive, community archive, 253 Remembrance Project, family stewardship, and contact pages.\n- Supabase schema foundation and security notes.\n- No fabricated memorial profiles or invented deceased people are seeded.\n\n## Run locally\nOpen index.html or serve the repository root with a static server, such as: python -m http.server 8000.\n\n## Supabase setup\nReview the SQL in supabase/migrations in a disposable staging project first. Prefer a dedicated Memorials project. Do not apply migrations to an existing CrowRules database without a separate review and backup. The browser must never contain a service-role key. The submission form is a non-persisting prototype until auth, database writes, storage authorization, moderation, and notifications are implemented and tested.\n\n## Editorial launch policy\nStart with a small, carefully researched archive rather than bulk-importing celebrity deaths. Public-figure and historical memorials require reliable death confirmation, source references, rights-cleared media, editorial review, and a correction route. A CrowRules-created memorial does not imply family endorsement. Verified family representatives may request stewardship. Living people must not be presented as deceased.\n\n## Visibility\nPublic memorials are discoverable only after approval and publication. Unlisted memorials are excluded from search and directories; direct links can be forwarded and are not confidential. Private memorials are restricted to explicitly authorized family members and managers. Platform administrators do not receive blanket access to private family archives.\n\n## Roadmap\n1. Public website and design system.\n2. Auth, family and organization membership, memorial profiles, submission workflow, moderation dashboard.\n3. Candlelight, tributes, galleries, memory books, gardens, and events.\n4. Family archive export, succession, backups, audit trails, and preservation procedures.\n5. Accessibility, security, privacy, and launch review.\n
