# Security, privacy, and storage\n\n- Public records must be explicitly approved and published before directory exposure.\n- Unlisted records must be excluded from search and directory queries. A direct URL is not confidential; sensitive unlisted content should require authenticated invitations.\n- Private records and files require verified membership checks on every request.\n- Use membership tables as the source of truth. Never trust client-supplied roles, family IDs, organization IDs, or owner IDs.\n- Recommended buckets: memorial-public, memorial-private, memorial-unlisted, memorial-audio, memorial-video, memorial-archives. Bucket names alone do not enforce privacy; apply object-level authorization and short-lived signed URLs.\n- CrowRules moderators must not have blanket read access to private family archives. Exceptional support access must be purpose-limited, approved, time-limited, and audited.\n- Use Edge Functions for privileged operations, invitations, verification, moderation, exports, and manager transfers.\n- Rate-limit submissions, candle creation, comments, and reports. Validate uploads and strip location metadata where appropriate.\n- Back up database and storage separately; test restoration and family archive export.\n- Keep secrets server-side. Browser code may contain only the project URL and public anon key.\n
